CORRUPTION-01 Corruption lib/import/validation.ts:128 Batch validation update silently skips rows on partial failure. buildValidationUpdateStatements for all rows in a batch are sent in a single writeBatch. If any single row's UPDATE fails (e.g., constraint violation from stale FK reference), the entire batch of updates fails. In the D1 adapter (adapter.ts:81-84), ANY non-success result throws, aborting all updates. In the SQLite adapter, the transaction rolls back. However, validateImportBatch does not catch or handle this — the error propagates to the caller with no partial results saved, meaning some rows that would have been marked "blocked" remain "pending" and need re-validation.
